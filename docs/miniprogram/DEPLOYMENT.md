# 部署准备（域名已购买，尚未部署或发布）

## 先确认资源

需确认：实名主体、AppID、备案情况、API 域名、服务器地区与供应商、可处理的播客来源、本地模型和付费预算。

内测采用一台 Linux 主机、Docker Compose、Nginx HTTPS、持久磁盘即可。容器示例限制为 4 CPU / 8GB RAM，但**这是模板上限，不是经过性能验证的推荐配置**。中文模型、长节目和 CPU 转写的实时率需在目标机器实测，再定规格；GPU 方案另行比较报价。语音模型包与权重另占磁盘，至少计入模型缓存、队列临时音频、SQLite 和备份容量。

预算公式：服务器月费 + 磁盘/备份 + 出网流量 + 域名续费 + 可选模型 API 费用。不能在供应商和规格未确定时给出可靠总价。注册、认证及备案办理要求以微信后台和接入商当时显示为准。本阶段无购买行为。

## 生产部署步骤（待确认后执行）

1. 准备服务器与 HTTPS 域名，按实际情况完成域名备案及小程序备案。
2. 在服务器项目 `deploy/miniprogram/` 下从 `.env.example` 复制出 `.env`，权限设为仅管理员可读；配置 AppID、AppSecret，勿提交 Git。
3. 选择本地模型，审核模型许可证、下载来源与资源需求。需要构建模型依赖时设置 `INSTALL_LOCAL_STT=true`，否则镜像仅能验证 API/搜索，真实转写会因缺少模型失败。先以授权样例完成模型预热和真实转写验收。
4. 项目根目录执行 `docker compose -f deploy/miniprogram/compose.yml build` 与 `docker compose -f deploy/miniprogram/compose.yml up -d`。这两个命令尚未执行；镜像构建会下载依赖。模板没有经过 Docker 实机构建验收。
5. Nginx 模板替换域名与证书路径，运行配置检查后启用。域名 DNS、安全组、证书续期与备案状态单独核验；仅公开 443/必要的80端口，8010仅监听回环地址，原有8000管理服务不对外开放。
6. 保持 `MINI_DEVELOPMENT=false`、`MINI_DEMO=false`。只运行一个 worker/副本。健康检查 `/mini/health` 应返回两项均为 false。
7. 小程序 `config.js` 改成正式 HTTPS 接口与 `developmentLogin:false`，填真实 AppID；微信后台配置 request/downloadFile 合法域名。正式包禁止关闭合法域名校验。
   - 当前正式AppID已配置为 `wxcf1571f64e71f165`；域名 `podnotes.cloud` 已注册 / 实名，尚未 ICP 备案；用户计划使用闲置电脑但尚无公网接入。详见 `DOMAIN_SETUP.md`，客户端仍保留本机开发配置。
   - 可从 `deploy/miniprogram/client.config.example.cjs` 准备生产客户端配置，替换示例域名后运行 `node scripts/check_miniprogram_release.cjs --config /绝对路径/client.config.cjs`。正式修改项目配置后再运行不带参数的同一检查。
   - 预检只读取本地文件，不上传代码、不调用后端、不读取密钥；它不能证明备案、TLS、微信白名单或后端生产配置已完成。目前预检应明确阻止开发登录和本机HTTP配置，不应为使其通过而提前伪填域名。
8. 真机联调微信登录、隔离、额度、真实搜索、长音频、后台恢复、失败重试、复制和 TXT 分享。根据实际处理方和存储策略完善隐私说明及微信隐私指引配置。
9. 通过体验版验收后再确认提交审核；审核通过后，正式发布另行确认。

## 备份与恢复

数据库位于 `mini-data` 卷的 `/data/mini.sqlite3`，启用 WAL。使用 Python/SQLite backup API 获取一致快照，勿只复制运行中的 sqlite 主文件而漏掉 WAL。备份应加密、限制权限，保留期限按最终隐私策略确定，不把备份放进公开下载目录。

恢复前停止唯一服务，备份当前卷，将一致快照恢复为 `/data/mini.sqlite3` 并处理旧 WAL/SHM，再以同一用户启动，抽样验证任务所属用户与导出；测试环境不要使用真实用户身份直接开放登录。

## 运维边界

- 当前是单机免费内测版本，无多副本抢占租约、无付费、无订阅消息。
- 微信登录在反向代理后会按代理 IP 计登录速率，模板限制保守；扩大内测规模前再设计可信代理和边缘限流，不能盲目信任客户端 X-Forwarded-For。
- 模型运行于带超时的子进程，容器对 CPU、内存、PID 限额；停止/重启可能中断任务。异常后不自动重新计费或重新运行。
- 目录缓存目前未做按容量淘汰，大规模使用前应增加过期与磁盘容量监控；当前内测规模需定期观察 SQLite 大小。
- 任务清理默认7天；备份、反向代理日志、微信客户端导出副本与第三方服务的数据保留需另外确认。不要把“删除任务”描述为能删除用户已分享的文件。
- 网络抓取校验公网 IP 并固定连接地址；仍应对运行容器施加网络策略，禁止访问云元数据、管理网段，并限制公网出口。
