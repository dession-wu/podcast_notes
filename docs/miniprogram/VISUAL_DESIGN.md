# 播客文字 · 阅读型界面改版

目标：像一份安静的播客刊物，用排版与留白组织内容，减少模板式圆角卡片、彩色提示块和重复按钮。

## 实施前设计规格

- 背景纸白 #F6F3ED；正文墨黑 #272923；辅助文字 #6B6D64；细线 #DAD6CC；强调朱红 #A4412D。无渐变、投影、玻璃效果。主要操作墨黑底，朱红用于标记与选中状态。
- 中文标题使用系统宋体族，界面控件使用系统无衬线字体，正文使用系统宋体族；无远程字体。标题 44–68rpx，正文默认 32rpx、行高 2，辅助文字不小于 23rpx。
- 页面横向边距 40rpx，控件触区原则上至少 72rpx 高，按钮圆角 6rpx；列表用细分隔线，不放入独立卡片。
- 首页：刊物式大标题“听过的，再读一遍。”，一体化搜索框，最近搜索为平铺文字入口，流程说明收为三栏。开发环境提示放到页尾但保持可见。搜索结果展示真实名称和作者，无虚构封面。
- 单集：节目标题、搜索与已加载范围、配额说明、分隔列表。生成按钮使用小型描边样式，时长与不可用状态保持可见。
- 我的文字：大标题、轻量下划线分类导航、任务状态小圆点与文字、日期、标题和提示。无虚构进度百分比。
- 阅读：宋体标题与宽松正文，正文直接铺在纸色底上，搜索与字号保留；复制与导出固定在底部，正文和删除按钮预留安全区。
- 图形：仅代码绘制的搜索、书页导航图标与列表方向符；不使用虚构播客插图或封面。底部原生导航保持两个入口。
- 交互状态：保留加载、失败重试、无结果、清空、筛选、超长限制、提交确认和删除确认，复制与导出始终使用完整正文。

## 工具与边界

采用 Frontend App Builder 的视觉规划与渲染检查方法。当前会话无可调用的 ImageGen 工具；备用绘图 API 需要额外授权与密钥，因此未调用，以上述原生设计规格作为实现依据，不声称已生成或获批概念图。项目是原生微信小程序，通过微信官方模拟器检查，不使用受限的 Work 浏览器。

不修改正式账号头像，不上传代码，不提交审核，不发生采购。截图中的测试文字明确标注为演示内容。

## 渲染复核与交付

1. 层次：首页宋体大标题、辅助说明、单一搜索入口；原先全宽按钮合入搜索框。模拟器发现原生按钮默认宽度挤占输入区域，已显式约束宽度。
2. 一致性：四页统一纸白底、墨黑正文、朱红强调、细线列表；导航图标由代码生成，与页面配色一致。
3. 内容适配：真实“知行小酒馆”搜索及 20 集 RSS 列表通过，长标题自然换行，超出 120 分钟的单集保留不可用提示。
4. 阅读与操作：字号切换、关键词匹配与清空通过；200 段本机样例可滚动到底，最后一段可搜索，末尾删除按钮与底部导出栏均可见。
5. 状态与真实性：空结果、任务状态筛选和失败提示均有原生截图；任务及文字使用明确标注的本机 UI 样例，未转写第三方音频，未发送文件或剪贴板。

验证：15 项客户端测试通过；微信官方 wcc（4 个 WXML）和 wcsc（1 个 WXSS）编译通过；微信官方模拟器交互检查通过，捕获异常为 0。截图见 `screenshots/editorial-redesign/overview.png`，运行记录见同目录 `real-catalog-validation.json`。

限制：本轮为本地开发版与单个模拟器视口验证，尚未进行安卓 / iOS 真机验收；不同系统宋体字体会有差异。没有生成式概念图，不声称与此类概念图像素一致。后续上线仍需生产部署与正式审核。
