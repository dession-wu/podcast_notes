# 转写速度、等待体验与精简版方案

用户提出三项问题：转写慢、没有可理解的等待提示、希望提供精简文字。此文为基于当前源码的方案评估，尚未实施本轮改造或接入收费服务。

硬件核实更新：用户日志(3).txt 显示 Windows 有 NVIDIA GeForce RTX 4060 Ti、16380 MiB 显存，驱动 576.52，nvidia-smi 报告最高支持 CUDA 12.9。此前 CPU 限制来自安装的 torch 2.11.0+cpu，而非没有显卡。官方 PyTorch 2.11.0 提供 cu128 包，拟先在现有独立 .venv 中替换匹配的 torch/torchaudio，验证实际 CUDA 运算和同一音频新模式。尚未完成安装或 GPU 转写验收，不推测加速倍数。核实后实施顺序调整为：GPU 实测与阶段计时优先，再处理常驻模型。原文对 CPU 环境下本地大模型竞争资源的分析是原环境前提；具备此 GPU 后，本地精简模型也值得另行评估显存、并发和质量，不能继续以“无可用 GPU”为由排除。

## 判断依据

目前 Mini API 仅一个队列消费者，每个任务单独启动转写 Python 进程；dialogue.py 每次创建 AutoModel，加载识别、VAD、标点与说话人组件。模型文件缓存会避免重复下载，但不会跨任务保留内存中的模型。这部分初始化有优化空间，实际收益需要分阶段计时。

Windows 新模型单人检查 651.11 秒含首次下载，不能作为后续任务预计时间；Windows dialogue 完整管线耗时尚未回传。Mac 自制 11 秒单人音频完整本地管线 26.75 秒包含进程启动及加载，并且下载被本地夹具替换，不能用于推算 Windows 一小时节目的耗时。

当前有排队、下载、转写、完成状态；阅读页和列表底部已有可离开提示，但提交成功后和处理中卡片不够突出，没有阶段计时或 ETA。现有后台任务实际在服务器运行，小程序退出不会主动取消任务；服务器关机、睡眠、进程停止仍会中断。

## 第一优先级：测量与等待体验

1. 保存任务提交、开始下载、下载结束、模型准备、开始识别和完成时间；采集音频时长、下载字节数、模式、模型版本和处理设备，不采集正文作为性能日志。
2. 提交后给出明确说明：“已加入任务。下载和转写会在后台继续，你可以关闭此页面或退出小程序，稍后到‘我的文字’查看。”处理中卡片与详情页持续显示同一信息，不将服务器配置细节放进用户界面。
3. 展示排队情况、当前阶段、阶段已用时；下载总长度可靠时显示字节进度，未知时只显示已下载量。缺少模型真实进度时不模拟百分比。
4. 初期显示“正在估算”。收集同服务器、同模式、相近时长的成功任务后，用区间估算剩余时间，包含排队和下载；异常速度下更新估计，不能直接用音频长度乘固定系数。订阅完成通知为后续可选能力，需另行确认微信模板与用户授权。

## 第二优先级：减少重复准备成本

1. 用受监管的常驻转写子进程保留模型，串行执行任务；API 继续独立运行，保留任务超时、崩溃重建和重启后恢复规则，避免直接将重计算放到 API 事件循环。
2. 模型可在服务启动后预热，明确首次准备状态；性能指标区分冷启动和热启动。内存使用需在 Windows 采集，不能承诺一个尚未测量的加速倍数。
3. 给任务提供快速文字和对话文字两个模式。推荐对话模式保留时间和说话人；快速模式省去说话人分离，优先保留句级时间。当前 basic/SenseVoice 不能直接视为已具备可靠时间戳的快速模式。
4. 评估更长音频的分块处理和先显示部分文字。分块必须保留全局时间偏移，并对齐跨块说话人身份，不能简单拼接每块的“说话人 1”；这部分晚于常驻模型和耗时采集实施。
5. GPU 或云端转写仅在实际时长测试后比较。涉及新硬件、云资源或付费 API 时，先确认预算与数据处理方，不自动启用。

## 精简版：保留原文，按需生成

产品采用“原文 / 精简版”双视图。原文是可追溯记录，精简生成独立异步任务，不延迟原文可读状态。精简版建议包含一段概览、主题要点、关键结论及能回到原文的时间引用，明确标注机器生成。默认用户主动点击生成；相同原文和生成版本复用结果，避免重复推理及调用成本。

精简可分两种能力：

| 方案 | 实际能力 | 代价与边界 |
| --- | --- | --- |
| 规则清理 | 分段、去除部分语气词与机械重复 | 不需要 LLM；需要保护否定、数字和重复强调，难以理解或重组长对话 |
| 大模型精简 | 提炼主题、合并重复观点、压缩表达 | 可部署本地模型或调用 API；要验证忠实度、长文覆盖率、遗漏和引用 |

生成质量好的语义精简通常适合用大模型，但不必使用外部 API。当前 CPU 服务器本地运行大模型会竞争计算和内存，因此若选择外部 API，优先采用按需生成、长度/次数上限、结果缓存、预算限额的方案；提供方、模型与价格暂未选定，不承诺费用数字。调用前确认费用上限及转录文本是否允许传给所选服务商，并同步隐私说明；不要求在聊天发送密钥。

长文本可按主题或带重叠的片段处理后归并，保留源片段 ID 和时间。模型只输出可验证的源片段引用，由服务端映射实际时间；不得让模型自行编造时间或将推断写成嘉宾结论。精简失败不影响原文。首期可用代表性单/双人节目人工评估，尤其核对否定、数值、归因和未覆盖章节。

## 验收顺序

先完成阶段计时与后台提示，再测同一台 Windows 上冷/热模型和 5/30/60 分钟授权音频；确认超时、离开重返、重启中断和并发排队可理解。随后上线常驻模型并比较相同音频的端到端耗时及资源占用。精简页和任务接口可先完成无调用的实现方案及样例评审；实际外部 API 接入和付费执行等待用户确认提供方、预算和文本外传范围。
