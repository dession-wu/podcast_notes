# 小程序交互优化验收

## 本轮结果

现有四页原生小程序已完成一次功能与视觉整理，保留青绿色风格和既有流程。没有改变公开内容、收费或授权范围，也没有上传代码、提交审核或发布。

| 页面 | 改动 |
| --- | --- |
| 搜索 | 最近搜索最多6条、本机清除记录、清空输入、结果数量、加载/失败重试/无结果提示、首次使用步骤 |
| 单集 | 按分钟/小时显示时长；筛选已加载单集；加载更多时保持筛选；明确已知超长节目不可提交；确认窗口显示选中标题、服务端额度和失败计次规则 |
| 任务 | 全部、处理中、已完成、失败筛选及数量；创建时间；状态颜色及具体阶段提示；筛选不会移除完整任务集合，后台活动任务仍会触发轮询 |
| 阅读 | 小中大三档字号、本机保存偏好；匹配文本段落数量和清空；全文字数与预计清理日期；明确筛选不改变复制/导出全文；防止重复删除请求；取消分享不再显示失败错误 |
| 视觉 | 统一标题、正文、说明文字、按钮和列表间距；减小单集操作按钮；提升禁用态对比度；补足底部安全区 |

## 验证证据

- Node客户端15项测试通过，含旧有登录、401刷新、离页停止轮询、弹窗限制与失败提示，以及新增最近搜索、分页筛选、时长限制、状态筛选、字号/全文复制与服务端限额映射。
- 发布校验新增缓存会话回归：即使已有token，生产环境错误开发配置也不能发送请求或下载。
- 微信官方 `wcc` 编译4份WXML、`wcsc`编译全局WXSS通过；8份小程序JS与9份JSON语法/解析检查通过。
- 官方 `miniprogram-automator` 在现有模拟器中实际搜索“知行小酒馆”，首批20集与单集筛选/清空通过，没有提交第三方音频。
- 任务和正文场景通过自动化向当前页面注入明确标注的本地UI样例，检查状态筛选、三档字号中的大字号切换、关键词计数与清空。没有在服务器创建这些任务，也没有验证真实任务生成或真实文件分享。
- 200段本地长正文样例可滚动到末尾，并能搜索第200段。这是长文本界面测试，不是长音频识别性能测试。
- 自动化未捕获JS exception；报告见 `screenshots/ui-iteration/real-catalog-validation.json`。本轮未单独收集所有console输出，不将其描述为零控制台错误。
- 新截图原图640×1386，拼图为缩略预览。已经目视检查首页、真实单集、示例任务、示例正文、无匹配状态、大字号筛选及长正文末尾：标题换行、按钮宽度、状态对比、空状态、底部删除入口可见，长文可正常滚动。

复现：本机真实模式服务8010、微信自动化9421就绪后执行 `node scripts/check_miniprogram_real_catalog.cjs --ui`。不调用浏览器控制能力；Work浏览器受限不会阻止可用的微信开发者工具联调。

## 发布预检

新增 `scripts/check_miniprogram_release.cjs`，只读检查正式AppID、开发登录关闭、HTTPS域名格式、URL敏感字段和公共域名校验设置。当前开发配置运行结果为：AppID/URL字段/公共域名校验通过，开发登录及本机HTTP两项阻止，退出码1，符合预期。没有为了使检查通过而伪填域名。

## 尚待完成

- 不同屏幕尺寸和iOS/Android真机的原生组件、剪贴板、文件分享、字号显示；本轮为单一模拟器尺寸。
- 正式微信登录、授权节目长音频、多人并发、真实离线/网络恢复；本轮UI样例不能替代这些验收。
- 当前仍为单机后端。域名、HTTPS、备案、生产部署与闲置电脑是否拆分worker仍待落实。
- 隐私说明仍是草稿，需要实际主体、联系方式、供应商和日志/备份保留策略；上线前必须定稿。
